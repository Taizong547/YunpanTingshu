## 第一章：先搞懂整体思路

### 这个APP是干嘛的？
简单说就是：**你把音频文件传到139移动云盘里，用这个APP随时能听，不用下载到手机。**

### 核心流程（一张图看懂）
```
你打开APP → 登录139云盘 → 浏览文件夹 → 点一个音频
→ APP向139要这个文件的"播放地址"（直链）
→ ExoPlayer拿到直链开始播放
→ 锁屏也能控制，定时自动停
```

### 为什么不直接用官方APP？
官方APP功能太杂，这个专门做听书体验：
- 跳过片头片尾
- 睡眠定时
- 倍速播放
- 书架收藏
- 播放历史统计

## 第三章：环境搭建（从零开始）

### 3.1 装 Android Studio
1. 去 developer.android.com 下载 Android Studio（最新稳定版）
2. 安装时勾选 Android SDK、Android SDK Platform
3. 第一次打开会自动下载 SDK 组件，等它下完

### 3.2 打开项目
1. 把项目zip解压到一个文件夹（路径不要有中文！）
2. Android Studio → Open → 选项目根目录（有build.gradle.kts那个）
3. 第一次打开会同步Gradle，等它下载完依赖（可能要10-20分钟）

### 3.3 跑起来
1. 用USB连手机，打开开发者模式、USB调试
2. 点绿色三角按钮（Run）
3. 选你的手机，等安装完成

**常见坑**：
- Gradle 下载慢 → 在项目根目录的 build.gradle.kts 里加阿里云镜像
- SDK 版本不对 → File → Project Structure → 改 compileSdk 为 34

## 第四章：核心代码逐行解释

### 4.1 一个网络请求是怎么发的？（Cloud139Api.kt）

```kotlin
// 第一步：定义请求
suspend fun listFiles(account: CloudAccount, folderId: String): String {
    // 先获取云盘的host（因为139有很多个服务器地址）
    val host = getHost(account)
    
    // 构造请求体（JSON格式）
    val body = JSONObject()
        .put("catalogID", folderId)
        .put("pageNum", 1)
        .put("pageSize", 100)
        .toString()
    
    // 第二步：发请求
    val resp = post(
        url = "https://$host/personal/v2/file/list",
        body = body,
        token = account.rawToken
    )
    
    // 第三步：判断成功失败
    if (resp.status == 200 && isSuccess(resp.body)) {
        return resp.body  // 返回JSON字符串
    } else {
        throw IOException("加载失败")
    }
}
```

**重点解释**：
- `suspend` = 协程函数，在后台线程跑，不卡UI
- `post()` 是我们封装好的方法，自动加请求头、签名
- `getHost()` 第一次会请求路由接口，之后缓存到内存

### 4.2 播放是怎么实现的？（PlaybackEngine.kt）

```kotlin
// 第一步：创建播放器
private val player = ExoPlayer.Builder(context)
    .setMediaSourceFactory(...)
    .build()

// 第二步：设置要播放的音频
fun playTrack(track: Track) {
    // 先获取直链（就是能直接播放的URL）
    val url = resolver.resolve(track)
    
    // 设置给ExoPlayer
    val mediaItem = MediaItem.fromUri(url)
    player.setMediaItem(mediaItem)
    player.prepare()  // 缓冲
    player.play()    // 开始播放
}

// 第三步：监听播放状态
player.addListener(object : Player.Listener {
    override fun onPlaybackStateChanged(state: Int) {
        when (state) {
            Player.STATE_READY -> { /* 可以播了 */ }
            Player.STATE_BUFFERING -> { /* 加载中 */ }
            Player.STATE_ENDED -> { /* 播完了，切下一首 */ }
        }
    }
})
```

**重点解释**：
- `ExoPlayer` 是Google官方的播放器，支持各种音频格式
- `resolver.resolve(track)` 是关键：把云盘里的文件ID，变成能直接播放的URL
- `prepare()` 是缓冲，`play()` 才是开始播

### 4.3 数据库怎么存数据？（AppDatabase.kt）

```kotlin
// 第一步：定义一张表
@Entity
data class HistoryEntity(
    @PrimaryKey val fileId: String,  // 主键
    val fileName: String,
    val positionMs: Long,  // 播放进度
    val playTime: Long     // 播放时间
)

// 第二步：定义DAO（操作数据库的接口）
@Dao
interface HistoryDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(entity: HistoryEntity)
    
    @Query("SELECT * FROM HistoryEntity ORDER BY playTime DESC")
    suspend fun getAll(): List<HistoryEntity>
    
    @Delete
    suspend fun delete(entity: HistoryEntity)
}

// 第三步：创建数据库
@Database(entities = [HistoryEntity::class], version = 5)
abstract class AppDatabase : RoomDatabase() {
    abstract fun historyDao(): HistoryDao
}
```

**重点解释**：
- `@Entity` = 这是一张数据库表
- `@Dao` = Data Access Object，操作数据库的接口
- Room 会自动帮你生成实现代码，不用写SQLite的重复代码

## 第五章：想改功能从哪里下手

### 想改UI样式？
- 布局文件在 `app/src/main/res/layout/` 文件夹里
- 每个Fragment对应一个xml文件
- 颜色在 `res/values/colors.xml`
- 字符串在 `res/values/strings.xml`

### 想加新功能？
1. 先想清楚放哪个页面（云盘？书架？我的？）
2. 改对应的Fragment布局加控件
3. 在ViewModel里加逻辑
4. 需要存数据就加Room表

### 想改播放行为？
- 播什么、怎么播 → `PlaybackManager.kt`
- 播放器内部逻辑 → `PlaybackEngine.kt`
- 播放队列 → `PlayQueue.kt`

### 想改云盘接口？
- 请求地址 → `Cloud139Urls.kt`
- 请求参数 → `Cloud139Api.kt`
- 签名/加密 → `Cloud139Signer.kt` / `OutlinkCrypto.kt`

## 第六章：怎么打包 APK

### 6.1 命令行打包（推荐）
```bash
# 进入项目根目录
cd YunpanTingshu

# Windows 用 gradlew.bat，Mac/Linux 用 ./gradlew
# 打包 Debug 版本（测试用）
./gradlew assembleDebug

# 打包 Release 版本（要签名）
./gradlew assembleRelease
```

打包完的APK在：
```
app/build/outputs/apk/debug/app-debug.apk
```

### 6.2 Android Studio 打包
1. 顶部菜单 → Build → Build Bundle(s) / APK(s) → Build APK(s)
2. 等构建完成，弹窗里点 locate 就能找到APK

### 6.3 Debug版和Release版区别
| | Debug版 | Release版 |
|---|---|---|
| 签名 | 自动用debug.keystore | 需要自己配签名 |
| 能不能直接装 | 能 | 能（但要签名） |
| 性能 | 带调试信息，慢一点 | 优化过，快 |
| 测试用 | ✅ | |
| 发布用 | | ✅ |

## 第七章：常见问题排查

### Q1：点播放没反应，进度条不动
- 90%是直链获取失败了
- 看logcat里有没有"获取播放地址失败"的提示
- 大概率是token过期了，重新登录

### Q2：登录页空白
- 139改了登录页的HTML结构，JS选择器失效了
- 打开WebView的调试模式，看看页面到底长啥样

### Q3：安装时提示"签名不一致"
- 之前装过别的签名版本，先卸载再装
- 或者统一用同一个keystore签名

### Q4：Gradle同步失败
- 网络问题，加阿里云镜像
- 或者离线模式：File → Settings → Gradle → Offline work
